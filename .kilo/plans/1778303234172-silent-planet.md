# Pfpad Resize Fix Plan — Complete

## Summary of All Changes This Session

### Root Causes Identified & Fixed

1. **Status bar `AutoSize` causing editor compression** — The status bar row in `mainLayout` used `SizeType.AutoSize`, causing WinForms to recalculate its preferred height during Snap resize. This created a feedback loop where `editorPanel` would shrink below usable width, making the minimap and text content clip at ~800px. **Fix:** Changed to `SizeType.Absolute 25px`.

2. **Minimap width scaled to zero** — `PositionMinimap()` used `Math.Min(MinimapWidth, Math.Max(0, availableWidth))` which made the minimap 0px wide when the panel was narrow. **Fix:** Always use full `MinimapWidth`; clamp X to stay on-screen; shrink width only to a floor of 1px.

3. **Layout timing race during live resize** — `this.Resize` fires mid-animation before `TableLayoutPanel` cascade settles, causing stale `editorPanel.ClientSize` reads. **Fix:** Added 50ms debounce timer (`_resizeDebounceTimer`) that coalesces rapid resize events and fires positioning after layout settles. Removed aggressive `this.Invalidate(true)` that triggered repaints during transitional states.

4. **Tab dropdown button hardcoded offset** — Used `scrollBtnArea = 55` regardless of actual scroll geometry. **Fix:** Dynamic detection via `GetTabRect(0).Left < 0` to know when scroll arrows are present; anchors right-edge with system scrollbar-width margin.

5. **`TabControl_DrawItem` index out of range** — `e.Index` could exceed collection bounds during forced repaints in layout transitions. **Fix:** Added defensive bounds checks against both `TabPages.Count` and `documents.Count`.

6. **Sticky scroll synced from wrong width source** — Was using `textEditor.ClientSize.Width`. **Fix:** Uses `editorPanel.ClientSize.Width`.

7. **Ruler feature added** — New `RulerPanel` control showing character-position tick marks at multiples of 5, with labels at multiples of 20. Theme-aware, scroll-synced. Placed between tabs and editor area.
