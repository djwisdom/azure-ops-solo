# Repo Summary Plan — Azure Ops Solo (focus: Pfpad Editor)

## Repository Overview

**Azure Ops Solo** is a single-developer ("solo") Azure infrastructure + personal application repository. It combines Azure ops automation (Bicep, Terraform, PowerShell patching, Azure DevOps pipelines) with a full-featured C# WinForms code editor called **PFPAD (Personal Flip Pad)**.

## PFPAD Editor — Deep Dive

### Project Identity
- **Namespace**: `MyCrownJewelApp.Pfpad`
- **Version**: **1.0.46.0**
- **Company**: Personal Flip Pad
- **Build metadata**: Git commit hash + UTC build date are embedded at compile time

### Architecture

The editor is a **single large WinForms application (~130 .cs files)** organized around the following subsystems:

#### 1 · Core Editor Shell
- `Form1.cs` / `Form1.Designer.cs` / `Form1.Roslyn.cs` — main window, layout, event wiring, Roslyn bridge
- `Program.cs` — entry point
- `SyntaxDefinition.cs` — language syntax configuration

#### 2 · Syntax Highlighting
- **Tree-sitter** (`TreeSitter/TreeSitterService.cs`) — incremental, multi-language parsing
- **ScintillaNET** — underlying text widget (see `docs/scintillanet-migration-analysis.md`)
- `HighlightRichTextBox.cs` / `IncrementalHighlighter.cs` — custom highlighter layer
- Supports **12+ languages** via Tree-sitter grammars
- Large-file guard: degrades features for files >50KB

#### 3 · Roslyn IntelliSense (C#)
- `RoslynHighlighter.cs`, `Roslyn/` (workspace, reference assembly)
- `CompletionPopupForm.cs` — auto-complete popup
- `SignatureHelpForm.cs` — method signature tooltip
- `HoverTooltipForm.cs` — hover info

#### 4 · Theming
- `ThemeManager.cs` — centralized theme engine
- `ThemeAwareMenuRenderer.cs`, `ThemedDialogs.cs` — theming enforcers
- **23 built-in themes** (dark/light, VS Code-inspired schemes)
- Windows native dark-mode (title bar, scrollbars)

#### 5 · Git Integration
- `GitService.cs`, `GitPanel.cs`, `GitForm.cs`
- `CloneRepositoryDialog.cs`, `DiffPanel.cs`
- Built on **LibGit2Sharp 0.31.0**

#### 6 · Debugging (DAP)
- `Debugger/DebugSession.cs`, `DebugAdapterProtocol.cs`, `DebugAdapterClient.cs`
- `BreakpointManager.cs`, `DebugCallStackPanel.cs`, `DebugVariablesPanel.cs`
- `DebugOverlay.cs` — overlay during debug

#### 7 · Performance Profiling
- `SamplingEngine.cs`, `PerformanceSample.cs`, `RingBuffer.cs`
- `PerformanceProfilerDialog.cs`, `DebugOverlay.cs`
- Sampling-based profiler with real-time overlay

#### 8 · UI Panels

## 6 · Implementation Ordering Recommendation

1. **Start with Phase 0** (bug fixes) — 2 h, unlocks macro replay and fixes dead code
2. **Phase 1** (motions) — high frequency in daily use, visible immediately
3. **Phase 2** (text objects) — transforms editing expressiveness significantly
4. **Phase 7** (macros) — uncomment 1 line, essentially zero cost
5. **Phase 3** (registers) — foundational; affects all yank/delete/paste paths
6. **Phase 4** (repeat) — amplifies new Phase 1+2 actions automatically
7. **Phase 5 / 6 / 8** — mix based on what surfaces most in user feedback
8. **Phase 9–13** — polish and advanced features last
